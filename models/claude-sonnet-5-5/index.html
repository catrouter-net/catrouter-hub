Claude Sonnet 5.5 是什么

Claude Sonnet 5.5 由 Anthropic 推出，2026年9月28日 发布，属于文本类模型。速度与智能最均衡的一档：Terminal-Bench 4.0 从 Sonnet 5 的 10.3% 直接拉到 70.6%，价格却仍在中端区间。

  • 能力跃迁：Sonnet 5.5 相对 Sonnet 5 在终端智能体任务上提升近 7 倍（70.6% vs 10.3%），首次让中端模型具备真正可用的长程 Agent 能力。
  • 成本结构：延续 Sonnet 家族的定价区间，适合大批量、高并发、对延迟敏感的线上业务，是替换 Haiku 与 Opus 之间的最佳中间档。
  • 迁移注意：官方列出 5 项破坏性变更，涉及预思考禁用参数、强制工具调用、thinking block 归属等，旧代码上线前需要过一遍兼容清单。
  • 多模态：支持文本与图像输入、多语言、视觉、工具调用，与 Opus 5.5 保持同一套 API 形态。

适合什么活

  • 线上客服与智能问答的高并发推理。
  • CI/CD 里的自动代码审查、单测生成与修复建议。
  • 日常知识工作：文档总结、会议纪要、结构化抽取。
  • 中长程 Agent：多步骤工具调用与任务编排。

国内调用会撞上的问题

  • 官方 API 国内访问不稳定，长连接容易被掐断，Agent 跑到一半失败需要重来。
  • 官方账号与支付门槛高，团队采购流程慢，临时验证需求经常卡在开卡环节。
  • Sonnet 5.5 用于高并发业务时，官方限流会直接打乱线上 QPS 规划。
  • 多语言 SDK 与 IDE 插件配置差异大，一套 Key 打通所有工具很难。

模型 ID 是 claude-sonnet-5-5，大小写与连字符都要一致。走 Anthropic 原生协议时 base_url 用 https://catrouter.net（不带 /v1）；走 OpenAI 兼容协议用 https://catrouter.net/v1。完整接入步骤见三步接入，报错对照表也在那里。

常见问题

Sonnet 5.5 适合替代 Opus 吗？

大部分日常任务够用，成本低一档；只在超长程、超高难度推理上仍建议用 Opus 5.5 或 Fable 5。

Terminal-Bench 4.0 分数为什么重要？

它衡量的是命令行环境下的真实 Agent 作业能力，比单纯的问答跑分更贴近工程落地效果。

能和中转站的自定义 Key 一起用吗？

可以。把 BaseURL 指向中转地址、Key 换成中转 Key，SDK 侧不需要改业务代码。
