三步接入与六个常见报错

拿到 Key、换 base_url、换模型名。绝大多数「连不上」都出在第二步的 /v1 上。

接入指南约 4 分钟更新 2026-11-09
地址先记两条：OpenAI 兼容协议 https://catrouter.net/v1（带 /v1）；Anthropic 原生协议 https://catrouter.net（不带 /v1）。

第一步：密钥

注册后在控制台建一把令牌，一把 Key 通用全部模型，不需要按模型分别申请。测试与生产建议分两把，便于单独限额。

第二步：两种协议

python · openai sdk
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的Key",
    base_url=https://catrouter.net/v1,
)
resp = client.chat.completions.create(
    model="claude-opus-5-5",
    messages=[{"role": "user", "content": "你好"}],
)
python · anthropic sdk
import anthropic

client = anthropic.Anthropic(
    api_key="sk-你的Key",
    base_url=https://catrouter.net,   # 不带 /v1
)
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好"}],
)

第三步：六个高频报错

报错真实原因怎么修
401Key 抄错，或用了别家的 Key重新复制，注意前后空格
404 model模型名写错或版本后缀漏了模型名写全，如 deepseek-v4-pro-0813
404 url/v1 重复或缺失OpenAI 协议带 /v1，Anthropic 协议不带
429并发或速率上限客户端加指数退避，别密集重试
超时请求体太大或跨境链路抖动缩小上下文、开流式、设置合理 timeout
流式中断长响应被中间层截断服务端加 keep-alive，客户端按 SSE 重连

还有一个容易忽略的点：Claude 的 thinking block 与产生它的账号绑定。多环境切换时不要整段搬历史对话，只带业务上下文。
