接不上时先查这几处

地址两条：OpenAI 兼容走 /v1，Anthropic 原生不带 /v1。十个连不上的问题里有六个出在这里。

接入指南约 4 分钟更新 2026-11-09

先把地址分清

OpenAI 兼容协议：https://catrouter.net/v1；Anthropic 原生协议：https://catrouter.net。同一个 Key，两套地址，混用会 404。

密钥

控制台建一把令牌，一把 Key 通用全部模型，不用按模型分别申请。测试和生产建议分两把，方便单独限额。

两种协议怎么写

python · openai sdk
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的Key",
    base_url=https://catrouter.net/v1,
)
resp = client.chat.completions.create(
    model="claude-opus-5-5",
    messages=[{"role": "user", "content": "你好"}],
)
python · anthropic sdk
import anthropic

client = anthropic.Anthropic(
    api_key="sk-你的Key",
    base_url=https://catrouter.net,   # 不带 /v1
)
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好"}],
)

报错对照

报错多半是什么怎么改
401Key 抄错，或拿了别家的 Key重新复制，注意尾部空格
404 model模型名不对，或版本后缀漏了写全，如 deepseek-v4-pro-0813
404 url/v1 多写或漏写OpenAI 协议带 /v1，Anthropic 协议不带
429并发或速率到顶客户端加指数退避，别密集重试
超时请求体太大，或链路抖缩小上下文、开流式、把 timeout 设合理
流式中断长响应被中间层截断服务端加 keep-alive，客户端按 SSE 重连

还有一个不太容易想到的：Claude 的 thinking block 跟产生它的账号绑定。换环境时别整段搬历史，只带业务上下文。
